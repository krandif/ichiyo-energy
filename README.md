# 一陽株式会社 社内システム（プロトタイプ）

住宅設備 × 訪問販売の業務基盤。太陽光・蓄電池・エコキュートの訪問販売から、施工・検収・売上計上・営業歩合までを一気通貫で扱う社内システムの設計プロトタイプです。

このリポジトリの `ichiyo-mock.html` は、画面イメージと業務フローの合意形成を目的とした**動作するモック**です。単一のHTMLファイルで、依存パッケージもビルドも不要です。

- タグライン: つくる・ためる・そなえる（西の光を、夜の安心へ）
- 対象エリア: 愛媛（西条・新居浜を起点に西日本へ）
- 位置づけ: 実装前の仕様確認用プロトタイプ。データはブラウザ内のJavaScript変数で保持（保存はされません）

---

## クイックスタート

`ichiyo-mock.html` をブラウザで開くだけです。サーバーもインストールも要りません。

```
# ローカルで開く
open ichiyo-mock.html          # macOS
start ichiyo-mock.html         # Windows
```

画面右上のトグルで **管理画面** と **営業アプリ**（スマホUI）を切り替えられます。

## このモックで触れること

### 縦串（1案件を最後まで通す）

営業アプリのマップから、1件の案件を訪問から売上計上まで流せます。操作するとヘッダーの数字・管理ダッシュボード・案件テーブル・マップのピン色が**同時に**更新されます。

1. 未訪問ピン（灰）をタップ →「訪問を記録」→ 訪問済（緑）
2. 訪問済ピンをタップ →「成約を登録」→ 契約済（青）＋クーリングオフ期間が発生
3. 契約済ピンをタップ →「工事完了・検収」→ 計上済（オレンジ）＋売上計上

「現場で1件動かすと、経営が見る数字まで自動でつながる」を体感するのが狙いです。

## 設計の考え方

### 技術選定：Twenty をコアに、freee と連携

スクラッチ開発ではなく、オープンソースCRMの [Twenty](https://twenty.com/) をセルフホストでコアに据える構成を採っています。

理由は、住宅設備×訪問販売で必要な機能の大半（顧客・取引先・商談・商品マスタ・担当者・リレーション・権限・一覧ビュー）がCRMの標準機能そのものだからです。ここをゼロから作ると、認証・権限・データモデル基盤・監査ログを再発明することになり、初版は早く出せてもその後の保守が負債になります。差別化にならない部分は既製品に任せ、独自ロジック（売上計上・地図ピン営業アプリ・歩合計算）に開発リソースを集中させます。

| 領域 | 担当 |
|---|---|
| 顧客・案件・商品・工事・在庫 | Twenty（セルフホスト） |
| 会計・売上仕訳・請求 | freee会計 |
| 給与・社会保険・歩合の変動手当 | freee人事労務 |
| 営業マンの地図・訪問記録・見積 | 自作モバイルアプリ（TwentyのAPIをバックエンドに） |

金額の計算はTwenty側、記帳・支払はfreee側、という切り分けです。計算ロジックをfreeeに持たせようとすると破綻するため、「いくら売れて誰にいくら払うか」はTwentyで確定し、「その数字を会計・給与として確定する」のがfreeeの役割です。

> ライセンス: Twenty は AGPL-3.0。社内利用のみであれば改変ソースの公開義務は発生しません（外部にSaaSとして提供する場合のみ考慮が必要）。

### 業務ロジックの要点

**売上計上は「検収完了」がトリガー**
契約締結ではなく、工事設置の検収合格の時点で売上を認識します。住宅設備の据付完了＝検収基準での収益認識が実態に合います。前受金がある場合は契約時に前受金として計上し、検収時に売上へ振替。二重計上を防ぐため、freeeの取引IDをTwenty側に保存します。

**2段階販売（Stage1 → Stage2）**
リフォームローンの枠（500万円）に収めるため、太陽光＋エコキュート（Stage1）と蓄電池（Stage2）を分けて販売します。Stage1設置後に発電・使用データが溜まった顧客を、システムが自動でStage2の見込みリストに載せます。Stage2は銀行借換で資金手当てするため、信販ローンに依存しません。これが2回目の売上機会になります。

**クーリングオフの管理（特定商取引法）**
訪問販売のため、契約日から起算した期間中は工事手配をロックします。営業アプリ・案件画面でカウントダウンを表示し、期間満了後に工事→検収→計上へ進みます。

**営業マンの可変報酬**
契約社員。ランク（S/A/B/C）ごとに固定給・アポ単価・成約単価が変わり、契約期間ごとにも変動、昇降格もあります。過去の任意時点の給与を正確に再現できるよう、以下の二層で持ちます。

- `RankMaster`: ランクごとの単価定義
- `RankHistory`: 「いつからいつまで、どのランクだったか」の履歴（イミュータブル）
- `RepContract`: 契約期間ごとの固定給（個人交渉での上書き）

キャンセル・クーリングオフが出た場合は、支払済み歩合をマイナス調整（クローバック）できます。

## データモデル（Twentyカスタムオブジェクト）

```
Supplier（仕入先: メーカー・商社）
Product（製品ライン）── ProductVariant（型番・スペック・価格）
PurchaseOrder（仕入発注）
Customer（顧客宅: 戸建て/マンション、緯度経度）
  └ Building（棟）── Unit（部屋）   ※マンション
Deal（案件・契約: 金額・ステージ・Stage1/2）
SalesRep（営業マン: 契約社員）
  ├ RankMaster / RankHistory / RepContract（ランク・報酬）
  └ Team（チーム編成）
VisitLog（訪問履歴: 誰がいつどの宅を）
WorkOrder（工事手配: 社内 or 外部委託）
Contractor（施工業者）
Installation（設置実績: 検収 → 売上計上トリガー）
ActivityLog（実績: アポ・訪問・成約）
Commission（月次歩合の確定額）
```

## 連携フロー

### 売上計上（検収 → freee会計）

```
Twenty: Installation.検収 = 合格  でworkflow発火
   ↓
freee会計: POST /api/1/deals  type=income（売上高／顧客／契約額）
   ↓
前受金があれば消込仕訳を同時起票
   ↓
Twenty: Deal.売上計上日 と freee取引ID を保存（二重計上防止）
```

### 月次歩合（Commission → freee人事労務）

対象月・対象repのランク履歴から適用ランクを確定し、`固定給 + アポ数×アポ単価 + 成約数×成約単価 −クローバック` を算出。freee人事労務へ当月の変動手当として連携します。

基幹の売上・給与はAPI直叩きで決定論的に処理し、月次チェックや例外処理は freee公式MCP（freee-mcp）経由でも運用できます。

## 実装ロードマップ（想定）

| フェーズ | 内容 |
|---|---|
| Phase 0 | TwentyをVPSにセルフホスト、バックアップ運用確立 |
| Phase 1 | コアオブジェクト（顧客・商品・案件・営業マン）定義、既存データ移行 |
| Phase 2 | 仕入・工事手配・設置オブジェクト、売上計上workflow＋freee会計連携 |
| Phase 2.5 | 報酬オブジェクト群を定義。まずExcelで正しさを検証してから自動化 |
| Phase 3 | freee会計・freee人事労務の本連携（OAuth・スコープ設定） |
| Phase 4 | 営業アプリ（地図ピン・訪問記録・見積）開発・配布 |
| Phase 5 | 運用データを見て権限・レポート・オフライン同期を調整 |

歩合計算は、数ヶ月分をExcelで手計算して実態と合うか確認してからコード化します。報酬は間違えるとトラブルに直結するため、いきなり自動化しません。

## 確定前に握るべき論点

- **売上計上の会計基準**（検収基準／引渡基準）、前受金の扱い、消費税の課税タイミング → 顧問税理士に要確認
- **歩合の締めと基準日**（成約日基準／検収完了日基準）→ 営業マンとの契約条件そのもの
- **クローバックの運用**（当月調整／翌月調整）
- **将来のFC・多拠点展開**の有無 → 展開するならマルチテナント設計が必要（Twenty無料版は多テナント非対応）
- **セルフホストの運用体制**（DBバックアップ、アップグレード手順）

## モックの技術メモ

- 単一HTMLファイル。外部依存はGoogle Fontsのみ（Noto Sans JP / Shippori Mincho / JetBrains Mono）
- データは `ichiyo-mock.html` 内の `DEALS` / `REPS` / `TEAMS` などのJavaScript変数。リロードで初期状態に戻ります（永続化なし）
- マップは実地図ではなくSVGで描いた模式図です
- レスポンシブ対応済み（デスクトップ・タブレット・スマホ幅）
- 登場する人名・顧客名・数値はすべてダミーです

### 注意

このモックは画面と業務フローの確認用です。以下は実装フェーズで対応します。

- データの永続化（ブラウザを閉じると消えます）
- 認証・権限
- 実際のfreee API / Twenty APIとの接続
- 地図の実データ（Google Maps等）
